# Build and navigate a world without losing its scene

Run the [shared procedure](README.md#shared-procedure) first. `F` is bound to this exact owned run; all parameter
names below come from `F info`, the controlled fixture or a freshly inspected UI tree. Complete every current
variant in this journey's coverage matrix, not only the numbered happy path. For each checkpoint record actual
commands, screenshot read/judgment, authoritative assertions, persistence where applicable and new logs in the
current-pass ledger. Missing fixtures are BLOCKED; planned/unrendered routes are audited exclusions until changed.

## User journey

1. Record fixture IDs and current hierarchy before changing it. Use the named verse tree/picker and cards to
   enter QA Basic, QA Fractal and Petal A. After every level read `F state --path navigation`; assert all ancestor
   IDs/names agree and downstream IDs clear when moving up. Read/judge the card counts and scene. Follow the
   canonical [S03 regression](S03-petal-navigation.md) using actual counts: fresh S7 A has three asset cubes plus
   an asset-free marker; B has a marker and terrain. A is map-free only in BASIC. Do not mistake marker rows for
   visible cubes. Enter B directly from the expanded sidebar while viewing the verse; verify the former crash
   path survives and the complete B ancestry appears. Return to A and compare stored transforms.
2. For each verse/fractal/petal, click its chevron separately from its active/inactive name. Capture collapse
   and navigation outcomes separately. A name click must not collapse away the current scene as a side effect.
   Open a long-named disposable entity and scroll its tree/card; check ellipsis/full hover and reachable actions.
3. Open the visible `+` / create control for each level, then resolve the dialog's name field:

   ```powershell
   F ui --interactive
   F type --into $qaCreateName 'QA disposable verse'
   F click --name 'Create' --role button
   F state --path navigation
   F api GET /api/v1/hierarchy
   F shot --label j01-create
   ```

   `$qaCreateName` is the exact current accessible field name resolved under the Create dialog, recorded in the
   ledger; it is not an arbitrary guessed string. Repeat for fractal/petal with distinct names and correct
   parent. Check blank-name disabled/refusal, Enter submission, Escape and Cancel on separate disposable forms.
   Each success creates exactly one durable row; cancel/refusal creates none. A failed Enter route remains a
   finding even if the Create button works. Exercise Add Node versus Add GLTF Model as distinct routes.
4. Select a node, open its Options, and compare NodeManager's `selection.node_id` with the node readback. Click a
   node in an inactive petal and check the actual navigation/selection behavior. No stale selection or mixed
   ancestry is acceptable. Cross-check J02's import/rename/delete routes rather than duplicating coverage claims.
5. Toggle the named eyes at verse/fractal/petal/node levels, then create a mixed visible/hidden rollup. Record
   each scoped visibility mutation through its UI and API readback. Hidden nodes must not be viewport-pickable.
   Repeat with inactive-petal rows and verify their guard. Exercise H, Shift+H, Alt+H and Escape-solo independently;
   distinguish persisted hide/show from session-only solo. Never infer durable state from one hidden frame.
6. Open Manage Groups / Groups. Add two groups, join/leave with the selected node, rename with Enter and cancel
   rename with Escape, reorder up/down, toggle visibility and delete with cancel/confirm. Check group IDs, names,
   order, membership and effective visibility through `/api/v1/petals/{petal}/visibility-groups` and node data.
   Exercise the actual configured cap/empty and Viewer-disabled states using controlled data and a real Viewer
   identity from J07. An Owner API token in the same Owner GUI is not a Viewer UI test.
7. Rename/delete disposable entities through existing Settings/Node Options, including an active ancestor.
   Verify hierarchy, navigation, selected entity and scene have no stale husk after deletion. Sidebar row menus
   F013 are planned in this snapshot: do not pretend the Settings route exercised them. When W2 adds them,
   promote their variants and run Rename, Settings, Copy ID, Delete-cancel and Delete-confirm explicitly.
