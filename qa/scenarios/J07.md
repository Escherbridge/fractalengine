## User journey

1. Open gears for verse/fractal/petal and General/Access/API tabs. Require correct entity scope and actual local
   role; a missing gear is a current route failure, not permission to replace it with an API settings write. Rename,
   Private/Public/Unlisted and Save Description must persist and survive reload. Test real loading/error states,
   not blank default values mislabeled as loaded. Use orphan-only Claim/Confirm Claim/Cancel fixtures, and check
   unavailable state for a normal owned entity. Delete-cancel/confirm uses disposable scopes.
2. Access badges currently show peer role/online status read-only; record that behavior without claiming a role
   assignment. F097 is planned until W3 wires server-authorized Assign/Revoke/downgrade. After it lands, add its
   actual controls, denial cases and second-host role change assertions, then refresh the denominator.
3. Generate invites for Viewer/Editor/Manager and each1h/24h/7d/30d expiry with a distinct disposable client/identity.
   Use Generate and Copy to Clipboard without capturing the secret-bearing frame. Join through the second host's
   actual Join Verse text field/Join, not an API-only substitute. Private fixture handling may carry the generated
   invite in memory through an explicitly authorized host seam; never log/screenshot/commit it. If no safe transfer
   seam exists, report the prerequisite BLOCKED and request the owning QA surface rather than reading host clipboard.
4. Join invalid/expired/already-joined and Cancel separately. Failed join keeps an honest inline error and no
   partial hierarchy; success opens a real live replica. An expired case requires a controlled expired signed
   fixture, not a random malformed string. Record both run IDs/ports and full cleanup identities.
5. In Inspector API Access test role, expiry and client, Generate/dismiss/Copy Token/Copy curl. Use no screenshots
   while a generated token is visible; leave the API tab to clear it before visual capture. API list metadata and
   redacted named controls prove the GUI route; separately verify cryptographic/client/scope behavior through the
   supported API/harness without pretending an API mint was a GUI interaction. No token values in output artifacts.
6. Exercise node/petal scopes, paging, Refresh, Revoke-cancel/confirm, revoked denial and an unrelated token still
   working. Repeat Entity Settings API scope/role/expiry/client/scoped revoke. Sensitive response artifacts must
   be redacted before storage; preserve stable IDs/claims metadata and actual allow/deny assertions.
7. Run the application as actual Viewer, Editor, Manager and Owner identities using separate owned roots or
   real remote grants. Check visible disabled reasons and independent server refusal. Downgrade remotely, then
   navigate between scopes while replies are pending; stale role must reset/re-resolve and never authorize a new
   scope by accident. A lower-role bearer token in the original Owner GUI does not exercise its UI role gating.
