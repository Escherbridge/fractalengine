# R-NET-5: adversarial review of the signed gossip plane, diagnostics and dial-back responder (+ F2)

Scope: `fe-sync/src/gossip_auth.rs` (NET-13), `fe-runtime/src/net_diagnostics.rs` + `fe-sync/src/net_diagnostics.rs` (NET-20, NET-28), the signing/verify integration in `fe-sync/src/distributed_query.rs`, `sync_thread.rs` and the `gossip_sig` latch in `sharding.rs` (NET-26), `fe-sync/src/virtual_transport.rs` (NET-27), `messages.rs` / `status.rs` (NET-28), `fe-sync/src/dialback_responder.rs` (NET-29). Diff base `7af0a144`. Refute-first, fresh context. No cargo was run. Security inbox read for every owned path.

SEC-INBOX 10: CONFIRMED-FIXED - fe-sync/src/distributed_query.rs:1658 - see N5-01.

N5-01 FIXED - fe-sync/src/distributed_query.rs:1658, fe-sync/src/sync_thread.rs:3830 - (HIGH, parser differential) the legacy latch check read claimed identities with a generic `serde_json::Value` parse and returned early for anything but a top-level object, while the handlers decode with typed serde decoders, which also accept a JSON array spelling (`["request", id, verse, from_did, ...]` for the internally tagged envelope, positional fields for `TilesetAd`). Such a frame skipped the latch yet was dispatched as the latched author. Claims now come from `decode_envelope` and a new `legacy_tileset_ad_provider` that wraps the handler's own `decode_tileset_ad`, so there is one parser. The admission journey adds the array-spelled request for a latched signer (refused `FORGED_SENDER_LEGACY`).
N5-02 FIXED - fe-sync/src/gossip_auth.rs:441,458, fe-sync/src/distributed_query.rs:1589 - (MEDIUM, replay across restart) a fresh process has an empty nonce LRU, so any captured in-age frame (compute 40 s, tileset ad 10 min, reach 60 s) replayed after a restart was admitted. `ReplayGuard::starting_at(now)` refuses frames clocked before the guard started (`PREDATES_SESSION`); the sync loop's ingress uses it. Cost: an honest frame sealed just before our restart is dropped (gossip is best-effort; peers re-advertise on NeighborUp). The replay journey adds the restart row.
N5-03 FIXED - fe-sync/src/sync_thread.rs:1091,1496 - (MEDIUM) closing a verse called `guard.forget_verse`, so a lease close followed by a reopen made every in-age frame of that verse replayable and dropped the session latch. Windows now outlive the close (still bounded by `MAX_TRACKED_AUTHORS`).
N5-04 FIXED - fe-sync/src/gossip_auth.rs:462,552,527 - (MEDIUM) an LRU-evicted window lost its nonces, so the evicted author's in-age frames became replayable; a member able to self-declare many `__peers` DIDs could force that. Eviction (and `forget_verse`) now raises `untracked_floor_ms`; a frame from an author with no window must be newer than it (`REPLAY_WINDOW_EVICTED`). Residual, fail-closed: during such a flood a newly seen author's first frames within the floor are refused. Journey row added after `forget_verse`.
N5-05 FIXED - fe-sync/src/sync_thread.rs:4162, fe-sync/src/dialback_responder.rs:219 - (MEDIUM, trust boundary) the responder required a declared Viewer+ requester but the requester accepted a `reach_result` signed by any did:key, including a stranger on the derivable topic, so a stranger could vouch that this node's relay URL is reachable. `handle_reach_result` now applies the same `DialbackResponder::authorize` to the prober, and `accept_result` refuses a record whose prober is the local node (self-attestation). Journey row added.
N5-06 FIXED - fe-sync/src/sync_thread.rs:4194, fe-sync/src/dialback_responder.rs:208 - (LOW, amplification) `broadcast_dialback_request` broadcast signed probes on up to four verses before checking the 16-entry pending table, so excess local requests still fanned out. `DialbackRequester::is_full` is checked first.
N5-07 FIXED - fe-sync/src/net_diagnostics.rs:178 - (LOW, correctness) peer rows carried `EndpointId::to_string()` as `peer_did`; fe-api's scope filter, the UI and the DTO doc all expect the did:key. Now `replicator::peer_did_key`.
N5-08 HANDED-OFF (fe-api/src/network.rs owner, next NET gate) - fe-sync/src/net_diagnostics.rs:170 - `node.downgrade_hint` names every open verse whose adverts omit the home relay; the API trims peer rows to readable verses but returns the node hint whole, so a viewer of verse A learns this node's other verse ids. Trim or genericize the hint in the scoped API path.
N5-09 KEPT (by design, bounded) - fe-sync/src/distributed_query.rs:1622 - signed frames from undeclared authors are verified but never recorded (no nonce memory), so they stay replayable within max age. Every handler refuses undeclared authors except tileset ads (idempotent, per-bundle BLAKE3 still checked) and compute responses (collector `answerer_view` rejects unexpected hosts, distributed_query.rs:321).
N5-10 KEPT (compat residual, documented) - fe-sync/src/distributed_query.rs:1640 - in Compat (the default) a legacy frame claiming an author with no latch yet (no `gossip_sig` row converged, no signed frame admitted) still reaches the F23 rules. A latched author cannot be downgraded: magic-prefixed bytes never fall through to legacy (gossip_auth.rs:386), and only the author itself can write its `__peers` row (sharding.rs:1976). Closed by `FE_SYNC_GOSSIP_SIGNING=require` or a manifest `gossip_signing: required`.
N5-11 KEPT - fe-sync/src/gossip_auth.rs:14 - cross-protocol reuse: gossip (`fe-gossip-v1\0`), dial-back (`fe-dialback-v1\0`) and relay adverts (`fe-relay-adv-v1\0`) are NUL-terminated, prefix-free domains; the frame `kind` is inside the signed body, so a frame cannot change handler (journey row "kind swapped after signing"). Reach probe/result reuse the gossip domain with distinct kinds.
N5-12 DEFERRED (trigger: any API that signs caller-chosen bytes with the node identity) - fe-database/src/invite.rs:73, fe-database/src/handlers/seed.rs:144 - these sign raw, undomained payloads with the identity key. Today their messages are structured text that cannot begin with a `fe-...\0` domain, so no gossip forgery exists, but a raw-signing oracle would create one.
N5-13 KEPT - key rotation and revoked DIDs: the latch and replay window are identity-only; authorization is decided per frame at handling time (`role_at` for compute requests, reach probes and now reach results; collector verdict for responses). A rotated key is a new did:key with its own window; a revoked DID's frames verify but are refused below Viewer.
N5-14 KEPT - fe-sync/src/virtual_transport.rs:121 - NET-27 is a contract doc; sim frames enter the same `SignedGossipIngress::admit` in the sync loop, so there is no sim-only bypass.
N5-15 KEPT (estimate, no benchmark run) - verify cost per inbound frame: one strict decode, a byte-exact re-encode, a second encode for the signing message (three payload copies), two did:key renders and one strict Ed25519 verify. Roughly 60-200 us per frame up to the 512 KiB cap, dominated by the verify for small frames and by the copies for large ones. A compute fan-out of N responders costs the requester N verifies on the sync loop: about 10-20 ms at N=100. Acceptable now; trigger to optimise (sign over the encoded body once, reuse it) is a fan-out above ~200 peers.
N5-16 KEPT - NET-20/28 redaction: the event and the Bevy status resource only ever carry the redacted snapshot (sync_thread.rs:1297); `detail` reaches only the caller's reply, and fe-api gates it behind owner role plus operator opt-in.
N5-17 DEFERRED (trigger: relay reconciler UI) - NET-08 handed NET-28 "show reconciler known/inserted in diagnostics"; not present in `NodeDiagnostics`. Display-only, no security impact.
