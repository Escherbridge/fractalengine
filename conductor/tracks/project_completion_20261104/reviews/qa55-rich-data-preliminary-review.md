## Recommended new finding

Recommend provisional **QA0074, S2: Custom-property row actions are offscreen in the default Inspector layout**. Register it separately from QA0039 hit-target sizing. This is a responsive layout and common-action accessibility defect, not evidence that the button dimensions alone are too small.

I inspected the actual 1280 x 720 PNG `.qa/run/20261104-174918-156/shots/175750-365-qa55-alpha-property-grid.png` (281,595 bytes, SHA256 `e7499447a0727e66bc592ff0a426620b9c191f64b9ce6fd013a827479bef27dc`). Fleet Alpha is selected; the Inspector displays Custom Properties with calibration, metadata, qa_fixture, schema_version, and telemetry rows. Values reach the right clip edge, while Edit/Copy/Delete are absent from the visible row area. The small text “Scroll horizontally for row actions” is visible, so this report does not assert that actions are permanently unreachable or that horizontal scrolling was tested and failed.

The saved `qa/passes/55/owner-alpha-grid-ui.jsonl` independently records the horizontal `Custom property table` content width as 496, body width as 260, and offset `[0,0]`. It reports the body's viewport height as zero despite the visibly rendered rows; that height is a telemetry limitation, not proof that the table was invisible. Each of the five rows places Edit at x=1300, Copy at x=1340, and Delete at x=1386, beyond the 1280-wide window. The respective recorded clipped hit widths are negative (-37, -77, -123), corroborating empty intersections at this offset. Button heights are 24–25 pixels and their un-clipped widths exceed 31 pixels. Thus all fifteen common row actions are offscreen at the default captured position even though their semantic nodes exist.

The already assigned UI repair should keep common row actions visible within the available Inspector width, using a readable responsive row/action arrangement or a stable visible actions control. Nested value previews may remain bounded and independently scrollable. Avoid requiring whole-table horizontal travel merely to discover Edit/Copy/Delete. Preserve property identity, typed values and whitespace, schema validation, current selection, pending/unknown writes, permissions, draft state, and clear destructive confirmation semantics. Acceptance should exercise actual Edit, Copy, and Delete on scalar and complex values at normal width and a narrow/high-scale configuration, verify resulting values/history, and inspect the actual screenshot and clipped control bounds. A hint alone is not sufficient acceptance for the requested accessible grid.
