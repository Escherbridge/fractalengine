## Real focus and current Owner QA capabilities

Locked primary source `bevy_egui-0.39.1/src/input.rs:1172–1184` sets each raw input's focused flag from its mapped Bevy `Window.focused`, unless the SDK's separate non-window focused-context resource is present. No production use of that alternate focused-context resource was found in `fractalengine/src` or `fe-ui/src`. Actual winit `WindowEvent::Focused` writes the Bevy window flag and emits `WindowFocused` (`bevy_winit-0.18.1/src/state.rs:362–365`).

The synthetic drag planner emits cursor settle, primary press, cursor move and primary release (`input_bridge.rs:455–457,494–500`); replay writes only the corresponding cursor/button messages (`:598–619`). It emits no `WindowFocused` event and does not request OS activation. Clicking a synthetic neutral point therefore cannot legitimately establish real window focus. Capturing or querying the tree also cannot establish it.

Owner QA's closed `WindowAction` enum has Size, UiScale, Maximize, Restore, Minimize and Close (`fe-runtime/src/qa_debug.rs:107–115`). The host translates these to the existing topbar executor or scale update (`qa_debug_bridge.rs:706–734`). `topbar.rs:425–440` unminimizes/restores/resizes where requested but never calls a focus API. OS-specific incidental activation during restore is not a guaranteed focus contract; size/restore acceptance receipts do not attest focus. Repeating those actions as a focus workaround would obscure the missing evidence.

The locked Bevy adapter has an actual `winit_window.focus_window()` call (`bevy_winit-0.18.1/src/system.rs:481–483`), demonstrating a real focus-request seam. A future sanctioned app-owned QA Focus action could use the existing primary-window chrome executor and actual winit window to request focus, with the same existing QA opt-in/loopback/root admission (`qa_debug_bridge.rs:651–659`). It must not set `egui::RawInput.focused`, synthesize `WindowFocused`, or assign `Window.focused = true` to claim success before an OS event. A request may be denied; only a subsequent real event/reflected input establishes eligibility. This is a bounded future option if fresh reasons establish focus as the missing predicate, not an implementation or acceptance in this report. It adds no external OS automation.
