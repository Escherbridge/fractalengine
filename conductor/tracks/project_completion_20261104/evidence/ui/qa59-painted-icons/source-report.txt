# QA59 painted core icons — isolated author candidate v1

Status: authored, not approved or executed. Independent source/design review is required before integration. The canonical source tree and frozen QA59 packet were not edited. The only writes are within `.omc/research/qa59-painted-icons-v1/`. No app/API/DB/native/network operation, Git command, parser, formatter, compiler, build or test was run.

## Problem and resulting source behavior

Actual QA59 screenshots show square placeholders for distinct core actions across the toolbar, Inspector and tree visibility gutter. The source used Unicode character strings without a guaranteed icon-font coverage contract. This candidate replaces those presentation strings with a closed semantic `Icon` enum and one small native-Button adapter. User data and text remain normal text, including Greek property keys. There is no added font, texture, dependency or fallback-font registry.

`ui_shell/icons.rs` reserves one fixed-size `Atom::custom` in an ordinary `egui::Button`, optionally followed by native text. `Button::atom_ui` supplies the actual custom rectangle after native layout. The adapter paints vector geometry there and returns the same native Response. It creates no child UI or second response, assigns no widget ID, handles no input, and owns no application state. The custom atom key is local to each returned atom layout and is not a global widget identity. Existing `.named`, tooltip, fill, permission and click ownership stay in their original callers.

The icon extent follows the resolved button font size with a 14-point cap. Line art uses 1.25-point strokes. The native target minimum is independent of this small paint extent. Circle/ring/square primitives reuse the existing tree palette renderer; other semantic symbols use simple lines/circles and filled disclosure triangles, following the existing caption/gimbal drawing idiom. Painting intersects the native Response rect and caller clip. The active/disabled/focus visual convention remains native: ordinary icon tint comes from the current native interaction visuals, an explicit tree tint remains explicit, and the caller's painter supplies disabled opacity. Existing selected-mode fills are retained with the toolbar/rail; no new selected flag or selection writer is introduced.

## Scope and inventory

- `panels/toolbar.rs`: `ToolDef.icon: Icon` replaces its glyph string; the seven tool names, shortcuts, tools and permission decisions are unchanged.
- `ui_shell/topbar.rs`: native painted tool buttons; the same Close presentation for labelled Deselect; Data/Options/Settings/Maps use the shared adapter too, keeping this visible toolbar boundary coherent. Original names, tooltip text, role gates and action handlers remain. The existing tool-activation journey finds native text by the same tool names, without the former symbol prefix.
- `ui_shell/right_sidebar.rs`: exhaustive section-to-Icon mapping replaces seven rail strings, including working old glyphs so the rail has one rendering convention. State toggle, active fills, names and tooltips remain unchanged. Its existing distinct-rail test now checks semantic Icon uniqueness and invokes the shared authored journey.
- `panels/inspector.rs`: both normal and compact Deselect paths share Close; the generated-token dismiss control reuses that presentation without changing token handling. Stored object/array disclosure chooses Expand/Collapse from the same existing `expanded` state. The previous native text-preview button remains native text plus the custom icon atom. No property draft, detail scope, value, pending gate, mutation callback or confirmation code changes.
- `panels/sidebar.rs`: the eye-button wrapper accepts a typed Icon rather than a string. Existing visibility booleans and rollup results choose Visible/Hidden/Mixed. Its callers, native enabled state, explicit accessible names, tooltip and click decisions remain. Existing tests calling this wrapper receive the same typed inputs.
- `ui_shell/mod.rs`: private crate module registration. Both local directory guides document presentation ownership and evidence limits.

The already painted tree appearance palette, hierarchy icons and caption-window controls stay unchanged. Existing visibility glyph APIs remain for other callers. Path-data glyphs and unrelated UI surfaces are outside the observed defect boundary; this is not a blanket Unicode rewrite. Native observer candidate files are untouched. Panel resizing/focus guards are untouched; this does not claim to resolve QA59's disabled splitter or achieve live 52/520-point bodies.

## Packet contract

`before/` contains the eight existing canonical files as read at authoring start. `raw/` contains their candidate replacements plus the new icons module. `source.patch` is a normalized unified source diff for human review; exact byte hashes in `manifest.json` and raw snapshots are authoritative for integration. `manifest.json` records each canonical mapping, before/raw sizes and hashes, patch/report hashes, and the prior visual report and frozen QA59 manifest anchors. Canonical source is compared byte-for-byte with its before snapshots during packet assembly; the new canonical icons module must still be absent. No self-approval is granted by these provenance checks.
