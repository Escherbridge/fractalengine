## Simplest safe integration

Add one bounded root-normalization operation to the existing full-tree identity machinery. Call it from `native_window_witness/provider_output::prepare` on the **actual owned output**, before provider_handoff and before any optional positive navigation aliasing. Derive destination from `OwnedRoot.window.to_bits()`; that root already binds the unique real Window, actual context and retained handler through `Ownership::current` (`fractalengine/src/native_accessibility/mod.rs:183–216`). Do not derive it from a context entity, PID/HWND, index, caller selector or new global allocator.

Implementation requirements for the approved design:

1. **Identify the real source root.** Require a standalone completed full tree with its one Role::Window root. The local seam has the expected egui source identity available as `ak::NodeId(egui::accesskit_root_id().value())`; Id::accesskit_id itself is crate-private, while value() is public and matches its implementation (`egui/src/id.rs:75–85`). Use the exact producer contract, not any arbitrary Window-shaped tree as permission to rename a node. If an idempotent already-normalized case is supported, define/check that case explicitly rather than interpreting an arbitrary replacement root as valid.
2. **Validate before and after.** Reuse existing MAX_NODES/reference-count/tree-closure checks. Reject missing root/focus, duplicate IDs, disconnected/cyclic/multiple-parent children, dangling references, wrong root role, destination collision with another real node, and destination collision with any issued private target alias/tombstone. Unavailable/poisoned alias-ledger state remains fail-closed. No probabilistic “entity IDs are small, so collision cannot happen” assumption.
3. **Translate exactly one identity everywhere.** Change only the original root node key, tree.root, focus when it names that root, and every currently supported relation/text-selection node reference through the existing rewrite function. Preserve all non-root physical widget IDs and all non-ID properties; preserve text-selection character offsets. Do not add a wrapper/synthetic node or reparent/sort the ordinary widget tree unnecessarily. Postvalidation must still establish complete closure with the same node count.
4. **Apply it independently of positive eligibility.** Both the positive navigation-mapped update and sanitized full fallback must have the same stable Window root. Putting normalization only inside the positive `mapping` callback would leave provider_handoff's fallback publishing the original egui root whenever no positive profile is available. That would preserve the activation race precisely during cold/ineligible frames. Normalize first; only then attempt navigation aliases or existing sanitized fallback.
5. **No raw fallback on normalization failure.** Empty/suppress the actual output slot, retire positive provider binding, retain quarantine and require a future independently validated full update. Preserve the existing alternate-publisher hold before Bevy AccessibilitySystems::Update. Do not let a failed normalizer return None and be mistaken for the existing benign positive-mapping failure that permits sanitized full fallback.

This separation is small and readable: physical root continuity is an invariant of the whole forwarded tree; positive navigation aliases remain a later, optional guarded transformation. Reuse validation/rewrite rather than maintaining a second relation list or separate tree cache. The existing `provider_identity::remap` remains responsible for exact target epochs, and the root must never become a navigation target.

## Transport classification is narrow and truthful

The existing Windows parent waits to deadline minus0.2s, then may call process.kill (`windows.py:230–238`) but labels a drained/confirmed result worker_exited regardless of having requested that kill. Installed CPython3.12 primary `C:/Program Files/Python312/Lib/subprocess.py:1667–1684` confirms Windows kill aliases terminate and uses TerminateProcess(handle,1). Exit1 is therefore compatible with a parent stop; it is not evidence of a C++ crash or provider HRESULT.

Remember only an actual deadline-stop request from this path. After existing confirmed wait and collector drain, a fixed `worker_deadline_stop_requested` code is an accurate statement of the controller's request, **not proof of why death occurred**. A natural-exit race can still happen between poll and kill. Collector/IO failure should remain primary; if an exception/lifetime/join path cannot confirm/drain, retain its existing unknown/failed ownership instead of upgrading it to a clean deadline result.

Controller must first durably record the actual terminal receipt, then refuse non-worker_exited classifications and unexpected actual helper exit values **before JSON decoding**. Expected helper exits remain exact integer0/2. Preserve any unexpected value in the existing receipt; do not synthesize a size or provider error from absent output. `_native_observer.ps1:256–260` already accepts bounded fixed terminal-code syntax and the exit-code numeric range, so this new categorical code needs no schema expansion or cleanup ownership bypass. Invocation reservation/intent and spent/unknown ledger outcomes remain authoritative; a refusal never resets them.
