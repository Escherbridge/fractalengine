## Residual findings

### [Adapter / small typed presentation strategy] — severity: high

**Location:** `fe-ui/src/panels/toolbar.rs:50-96`; `fe-ui/src/ui_shell/topbar.rs:524-525`; `fe-ui/src/ui_shell/right_sidebar.rs:1769-1814`; `fe-ui/src/panels/inspector.rs:228,1961-1966`; `fe-ui/src/panels/sidebar.rs:135-154`; `fe-ui/src/visibility/resolve.rs:309-329`.

**Current:** Multiple unrelated controls paint the same hollow square placeholder where their intended symbols differ. The 1x toolbar has boxes preceding Move/Scale/Pen/Brush; the Inspector rail has boxes among otherwise recognizable wrench/gear/map symbols. At 2x the Deselect control is a box, as are the object-summary disclosure marker and many tree visibility controls. This is a real rendered affordance defect, not text elision. A square used intentionally for Select cannot alone prove missing coverage; the clearly non-square source characters for Move U+271B, Pen U+270E, Deselect U+2715, disclosure U+25B8/U+25BE, and visibility U+25CF/U+25CB establish the mismatch across surfaces. The primary hierarchy icons already use painted shapes and render properly.

**Suggestion:** Use a small shared semantic icon adapter with egui Painter primitives for these core controls, following the existing `TreeIcon::paint` in `panels/tree_appearance.rs:25-68` and painted caption buttons in `ui_shell/topbar.rs:277-335`. Keep accessible names, existing Response identity/action handlers, hit sizes, colors and disabled/selected state with their current owners. A focused catalog of presentation variants suffices; it does not need a new action system or global state. Alternatively install and explicitly select a known font with measured coverage for every required symbol. Merely choosing another BMP character is not sufficient evidence: the current documentation already calls visibility glyphs BMP-safe, but these captures contradict that assumption. A scoped Rust-source search found no application `set_fonts`, `FontDefinitions`, `font_data` or `FontData` customization. That narrows the source trace to text-glyph use without an app coverage contract; it does not prove a GPU renderer defect or identify the exact fallback font at runtime.

**Example:** Keep `named(ui, "Deselect object")` and its click handler unchanged, but have a shared `Icon::Close.paint(painter, icon_rect, stroke)` draw two thin line segments inside the existing Button response. Likewise draw disclosure triangles and visibility circle states from semantic variants instead of relying on their Unicode strings. The adapter draws only; the current caller retains interaction and accessibility ownership.

**Impact:** Icon-only actions regain distinct visible meaning across font fallback and scale settings. A single presentation implementation stays editable and avoids repeating font assumptions across panels. Verify actual PNGs for the icon-only rail, Deselect, disclosure, visibility on/off/mixed, and tool buttons at 1x/2x after the change. Preserve user property text and Greek content as text.
