## Design and ownership assessment

**Value object and one policy predicate — sound.** `layout_policy.rs:162-211` introduces small fixed-field `DividerGates` and `DividerEligibility` values. The finite static blocker chain is easy to read, has no arbitrary context text or callback machinery, and reports all boolean inputs alongside the first blocker. The full public blocker delegates to the same interaction blocker plus the existing release latch. The renderer and serializer do not reconstruct the gate independently. No strategy trait, builder hierarchy or separate policy service would improve this small boundary.

**Existing state machine stays authoritative — sound.** `PanelWidthState` still exclusively owns the preferred width, preview/capture, prepared/layout geometry and release latch. `set_interactive` is a narrow adapter for the existing hierarchy/general boolean gate. The right caller supplies its original dialog/close facts explicitly; `quarantine` preserves them while setting its own fact. These operations suspend under the same effective false condition as the old boolean setter. The next right render resets named caller facts before reevaluating quarantine, matching the original per-render reset behavior.

The right predicate remains `(None or HexonManager dialog) AND not close_pending AND not quarantined`, followed by the unchanged focus/Escape/popup/modal requirements. The hierarchy's existing `resize_interaction_allowed` boolean is still applied and is truthfully represented as its generic app gate; this candidate does not claim to decompose that caller's internal reasons. It does not silently relax a disallowed dialog, quarantine, pending close or lost focus.

**Separate decision times are necessary — sound.** `prepare` evaluates the interaction component before consuming the previous Response, while retaining its separate geometry/pass-freshness and release-latch handling. `register` reevaluates after panel contents, which can open a popup/modal. That timing is unchanged. At registration one captured `eligibility` value controls the disabled UiBuilder and supplies the observation. The actual native `response.enabled()` is recorded separately. Reusing an earlier prepare decision here would have been stale; the candidate correctly avoids it.

The original geometry validation, pass continuity, existing IDs, layer, strip, registration order, pointer thresholds, finite checks, drag lifecycle, preferred-width commit and suspension paths remain. No new width setter, input writer, focus event/request, pointer capture release or parallel state owner appears in the diff.

**Observer with bounded lifetime — sound.** `register` appends facts only after a real valid divider surface and native Response exist, only when existing LayoutObservations are enabled, and only while fewer than two records exist. It neither invents a record for a missing/invalid/hidden surface nor guesses why registration did not occur. A record carries the actual divider ID, fixed side, cumulative pass and captured flags. The existing `begin_ui_pass` resets the entire collector, including this new vector. The normal `gardener_console` calls that reset before rendering either side; the host reads it after egui output. Thus these are pass-local observations of registered controls, not a retained cancellation log. The cap can omit further registrations; absence remains unknown rather than being interpreted as an eligible or absent panel.

**Read-only serialization facade — sound.** `qa_debug_bridge.rs:215-241` adds version1 and a bounded array to the existing layout serializer. It uses the saved value's same blocker function and exports only fixed booleans, ID/side/pass and the actual enabled flag. It adds no route, request parser, dynamic dialog payload, handle, credential, clipboard field, native proof or mutation. Existing layout fields remain intact. Existing default-off typed Owner/rate admission in `fe-api::qa_debug`/`operator_gate`, host current ViewScope check, same-frame navigation check and primary-context check remain on this route; none are changed by this candidate.

The directory documentation correctly distinguishes `egui_input_focused` from AccessKit widget focus and from independent OS focus proof. The native Response enabled flag is likewise distinct from recorded layer permission, visibility/occlusion and successful input acceptance. This is enough to explain the observed disabled divider without exporting a second interaction authority.

## Authored verification and practical limits

The existing width journey now checks actual captured decisions against the registered Response ID/pass/enabled flag and the two-record bound. Its added dialog/quarantine, pending close before modal paint, Escape, focus-loss, held-release rearm and unchanged preference assertions exercise the production decision/state methods. The original drag/cap/scale/collapse geometry coverage remains. The harness supplies caller facts rather than introducing a parallel resizing implementation. No new standalone registered test or runner is added. These are meaningful **authored, unexecuted** assertions.

The candidate's `eligible` means that the recorded registration-time surface policy has no listed blocker. It is not complete drag admission or success: geometry/pass freshness, an earlier canceled gesture, actual hit ownership/occlusion, a later popup, the actual target, and a committed width still require their corresponding evidence. A missing record does not diagnose those paths. The separate `response_enabled` and flags preserve this distinction rather than silently converting an unsuccessful command into an accepted interaction.

This source review does not identify QA59's historical failed guard. In particular, existing AccessKit `focused:false` is not evidence that `egui_input_focused` was false.
