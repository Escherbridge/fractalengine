# Require-existing startup design v1

Design only, 2026-11-04. **Recommend one typed retained-startup branch in the existing GUI and sole DB owner, backed by a proven existing-store admission seam. Current retained roots remain on HOLD.** The application changes are bounded; the missing SDK admission mechanism below is a real implementation prerequisite, not a proven API. No source, SDK, launcher, store or Conductor file was changed by this design lane.

## Contract and scope

Hard requirements from the retained-startup source trace and `conductor/tracks/project_completion_20261104/reviews/volume-live-security-plan-review.md:136–145`: no accidental replacement store/namespace/schema, seed, identity regeneration/healing, reconciliation, asset/role migration, offline second opener, invented DID/provenance or rewritten baseline. Validate the real persisted bootstrap Verse owner against the actual persisted node key before application logical initialization, shared-handle publication, sync/API/token service. ResumeRun fixture suppression alone does not establish this.

**Zero physical writes is a separate, stronger requirement and is not adopted here.** The source trace expressly separates logical no-init/no-seed from storage-engine housekeeping. Existing-store lock bookkeeping, valid WAL replay and ordinary engine maintenance can change physical files without creating a replacement logical store or granting ownership. Positive restart acceptance therefore compares logical records/history/blob/identity invariants and separately reports maintenance; it does not promise every database file hash remains equal. Corruption repair, discarded WAL contents, storage-version migration or a missing engine catalog are not routine maintenance in this v1: refuse rather than silently heal them. Any stricter requirement for zero physical changes needs an explicit decision and a supported nonmutating engine open, not an inferred blocker.

This design also defers SurrealDB's own logical bootstrap until owner admission, avoiding reliance on classifying its cluster writes as harmless application initialization. It does not attempt a second connection or close/reopen between validation and service.

## Selected implementation shape

Use an enum such as `StartupPolicy::{Normal, RequireExisting(ExistingExpectation)}` and an owned guard/session that transitions `Pinned → Admission → Accepted → Serving`. Names are proposed application types, not claims about available SDK APIs. Keep existing compatibility wrappers normal by default; the GUI's retained launcher selects RequireExisting explicitly. No boolean scattered among seed/reconcile call sites, alternate DB thread, helper or generic query endpoint.

`ExistingExpectation` binds the exact run/root, retained bootstrap Verse ULID, existing DB subpath and loaded node-key identity. The DID is derived in-process from the actual loaded key. Canonical stored created_by equality supplies the owner test; do not invent a new requirement that ordinary old current.json already contains an original DID. A separately claimed historical original-owner fact still needs its original witness and must remain unknown when absent.

### Ordered lifecycle

1. **Launcher preflight before stopping anything.** Under the common lifecycle/per-run transition protocol, validate stage capability/provenance, supported retained mode, immutable current/start records, actual store/key/secret availability and pair constraints. Refuse an unsupported stage or legacy path before Stop-QaNativeObserverWorkers or app stop. Capture exact existing path/file identities, scoped expectation and a fresh per-start correlation; no secret values in environment/arguments/logs. Fresh launches explicitly clear retained-policy variables. Archive old outcomes and stop only recorded identities through existing ownership rules. Failed new admission stays a failed attempt, never fresh fallback or automatic retry.
2. **Earliest app admission.** Parse policy before qa_storage_root/create-parent helpers, CWD-dependent persistence, blob/network setup and generated identity. Open existing nonredirected ancestors/identity leaves only. Read one bounded captured node-key file and required secrets snapshot; parse existing key slots, verify file-key and secret-key agreement and load existing share signer. Missing/corrupt/disagreeing material refuses without generation, secret set, keychain fallback, permission healing or ephemeral signer. Keep bytes private and loaded objects stable. Retain identity leaf/ancestor pins through startup admission; identity replacement cannot substitute a new key between validation and use.
3. **One confined DB owner.** Pass the typed policy plus owned path/identity guards to the current worker. Require the exact existing engine root/catalog/format, namespace/database and required schema. Missing/corrupt/incompatible state refuses, never creates. One exclusive engine ownership lifetime must cover validation through serving. On Windows, retain nonreparse ancestor handles denying path replacement/deletion and actual opened object identities; do not rely on check-then-open canonical strings. Protect required admission catalog identity until the engine owns the same store; compare the actual opened store/manifest/lock identity with the expectation. Existing lifecycle locks cover cooperating launchers; they are not a substitute for actual handle/path binding or a defense against unrestricted same-user memory tampering.
4. **Read-only logical admission before SDK/application bootstrap.** In that same engine/session, validate storage version as existing, namespace/database metadata as existing and schema compatibility without add/get-or-create operations. Read exactly the retained Verse by bound ULID with cardinality limit2, reject missing/duplicate/malformed owner and require created_by equals the actual key's DID. Require no placeholder local-node fallback. Any required schema/role-cache incompatibility yields a migration-required refusal, not initialization. Recover clocks using checked reads after admission; errors cannot silently initialize clocks to0. An empty valid history may legitimately yield0.
5. **Accept once, then serve.** After a successful same-session owner/schema/version admission, enable only necessary SDK serving/bootstrap work while retaining engine/path ownership. RequireExisting always skips application DDL/reconcile/base64 and imported-asset backfill/role migration/Seed, including a later queued Seed command. Publish a typed accepted result and shared handle only when this retained branch is complete. Main waits for that result instead of submitting Seed; normal startup keeps its existing seed/result replay path. Only then start network/sync, API/dev tokens, UI hydration and other persistent services. A startup receipt records public derived node DID, retained bootstrap scope, actual store identity, policy version and completion, without key/token bytes. Fresh client token subjects remain distinct.
6. **Legacy and pair behavior.** Keep exact pair membership/birth/bootstrap reseal rules; policy acceptance does not reset prior native outcomes. Legacy restart can remove the refused offline-helper prerequisite only when the reviewed live-owner path validates its existing preparation/asset context without regeneration or adoption. Otherwise refuse pre-stop. No copy of a retained DB, fake uploader, invented operation ID or retrofitted owner field is permitted.

## Exact unresolved mechanism and bounded decision

**The current ordinary SDK connection cannot be asserted to implement steps3–4.** The unresolved mechanism is an existing-store, no-create catalog open with a same-engine admission phase before SurrealDB version creation/bootstrap/router tasks, bound to actual protected store identities. This is narrower than prohibiting every lock/WAL write. Do not authorize a retained open merely because the app branch now skips Seed.

Preferred next bounded engineering lane: source-design and independently review that seam against the locked SDK. First determine whether a supported existing mechanism can provide its exact contract. If not, propose a small pinned upstream/vendor change (separately approved dependency/source scope): require existing directories/catalog; load existing manifest with no create fallback; acquire/check actual existing lock/store identity; read existing storage-version metadata without creating it; expose a private admission phase/callback before logical SDK bootstrap, then promote the **same** ownership/session. Preserve valid physical recovery while refusing corruption repair or incompatible format. Admission-query capabilities must be read-only at execution, not a convention on caller SQL. The callback/API signatures and platform identity transfer still need concrete source review; they are not implemented or assumed here.

Do not substitute a general raw-KV reader, read-only SQL after ordinary open, unsupported bypass of the SDK router, permissive version initialization, physical snapshot copy or close/reopen without continuous ownership. If only an existing-only open with pre-owner SDK logical bootstrap is implementable, record that exact weaker contract for an explicit review/decision; it does not silently satisfy this design. The stronger zero-physical-write alternative is a separate product/acceptance choice and remains unrequested. Until the selected seam is proved, retain the current hold and do not stop retained runs in expectation of an unsupported restart.
