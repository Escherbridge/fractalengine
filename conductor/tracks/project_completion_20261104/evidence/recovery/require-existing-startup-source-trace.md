# Require-existing QA ResumeRun: source trace and proposed boundary

Source-only investigation, 2026-11-04. This is a plan, not implementation or runtime acceptance. Retained campaign stores remain on HOLD. No DB was opened, app/helper started, process/OS/API/network observed, parser/compiler/test executed, production edited, or Git mutation performed. Read-only shell file inspection was used. Other authors own native observer and scene recovery/status changes; this note changes neither.

## Current launcher flow

- `tools/qa/restart.ps1:19` forwards supplied options to `launch.ps1 -ResumeRun`.
- `tools/qa/launch.ps1:27-58` resolves the retained run, stops native observer workers, takes the common lifecycle lease and per-run restart lock, rereads context, refuses a supplied Fixture, and inherits options.
- `_lib.ps1:247-300` (`Get-QaResumeContext`) confines the direct run child, rejects reparse storage, checks nonempty `data/fractalengine.db`, `identity/node_keypair.key`, `identity/secrets.json`, and copied assets. It validates current.json, exact bootstrap Verse ULID, stage/exe provenance, process identity and loopback origin. These are filesystem/lifecycle checks, not DB contents or owner checks.
- `launch.ps1:94-117` archives previous start metadata and stops only recorded identities. Legacy-adoption then calls `Read-QaLegacyFixture -Phase resume` and unconditionally refuses through the stopped-store helper. Thus this legacy branch can stop a run without restarting it.
- Resume skips fresh root/assets, terrain generator and REST fixture creation. It removes old tokens.json, starts the staged app with run-local environment and new attempt logs, waits for health, a fresh Owner token for the retained bootstrap Verse, and authenticated hierarchy readiness. It then replaces current.json and writes `restart.reseeded=false` (`launch.ps1:165-325`). That flag currently describes launcher fixture behavior; it does not prove the app never dispatched seed.
- The scoped environment currently carries storage, input/timing, port and relay overrides, but no require-existing startup policy or expected retained scope/owner contract.

## Current application and DB startup

1. `fractalengine/src/main.rs:40-68` resolves QA root, confines overrides and changes CWD. `qa_storage_root` uses `pin_secret_parents`; that helper can create missing parents (`fe-identity/src/file_fallback.rs:11-62`). A future strict-existing path must reject missing ancestry before any create-capable helper.
2. `main.rs:149-214` constructs RunLocalBackend, loads **or generates** the file-tier node key, and always writes that key to secrets.json. RunLocalBackend permits missing secrets.json as an empty map (`fe-identity/src/secret_store/run_local.rs:52-65`). `main.rs:240-246` loads/generates share signer and falls back to an ephemeral signer on failure. None is a load-only retained startup contract.
3. `main.rs:285-306` gives the actual keypair and DB path to the one `spawn_db_thread_shared` opener. Compatibility wrappers funnel to it (`fe-database/src/lib.rs:386-485`).
4. Worker `lib.rs:517-538` opens SurrealKv with its ordinary create-capable path, selects namespace/database, then applies RBAC and API-token schema. There is no typed existing-only admission or persisted owner comparison.
5. Worker recovers persisted clocks and publishes `Ok(db.clone())` through the startup rendezvous (`lib.rs:541-568`). Only afterward does it derive `local_did` (with `local-node` fallback when keypair absent), reconcile, migrate base64 assets, backfill imported assets, and run role-grant startup (`lib.rs:570-616`). These paths can change logical data or blobs. Shared-handle return is therefore earlier than full initialization completion.
6. `main.rs:353-392` **always** submits `DbCommand::Seed`, waits for `Seeded`, and replays captured results. Worker `lib.rs:654-660` always permits that command. `handlers/seed.rs:87-105` skips only when a row named Genesis Verse exists. A nonempty retained store without that row can receive new Genesis hierarchy/assets. This defeats a never-seed guarantee even if a normal retained run happens to skip.
7. Only after this barrier does main start sync; API reader/entity cache hydration and API startup occur later (`main.rs:630-737`), followed by dev-token service (`main.rs:740-756`). UI hierarchy load occurs when the app runs. Health/token/readiness success is too late to protect startup data.

## Identity facts and missing invariant

Persisted `verse.created_by` is the canonical Owner identity. `fe-database/src/role_manager.rs:19-39,63-68` resolves Owner by exact equality with that stored creator. A retained bootstrap Verse is already pinned by current.json's bootstrap_verse_id. Its exact stored owner must equal the actual DID derived from the existing run-local node key **before logical initialization, shared-handle publication, sync, API or token minting**. A placeholder, missing/duplicate/malformed Verse, foreign owner or missing/corrupt key must refuse; never claim, heal, regenerate or choose another scope.

Ordinary current.json contains no general original node DID. Windows process identity is not node identity. `fixture_detail.runtime_did` in legacy preparation is especially unsuitable: `Get-QaLegacyRuntimeDid` (`_legacy_fixture.ps1:59-71`) decodes JWT **sub**. The dev-token service intentionally uses a fresh client DID each process (`fractalengine/src/AGENTS.md` QA dev-token section). That field is not an original node/DB-owner witness. Do not reinterpret or rewrite it, derive authority from a fresh bearer, or invent a DID. If comparison with a separately frozen original owner is required, use an already retained true owner witness; missing provenance must remain an explicit blocker.

## Minimal implementation plan for independent review

1. **`tools/qa/launch.ps1`, `_lib.ps1`, `restart.ps1` (root lifecycle ownership):** make ResumeRun select an explicit typed require-existing policy; pass the existing bootstrap Verse ID and any required already anchored owner identity through scoped startup arguments/environment. Fresh launch must explicitly clear inherited require-existing values. Validate missing policy/provenance before stopping anything. Keep exact process cleanup, staging hashes, current.json provenance and immutable prior attempt records. Do not call the refused offline legacy SDK helper as a restart prerequisite; replace that boundary only with separately reviewed live-owner checks, otherwise refuse before stop.
2. **`fractalengine/src/main.rs` and a narrow startup module if needed (root ownership):** parse/validate policy before create-capable root/key/secret helpers. In retained mode require an existing confined root, load the existing node key only, read existing required secrets only, and reject missing/corrupt/mismatched identity instead of generation, healing or ephemeral fallback. Pass typed expectations to the DB owner. Replace unconditional Seed barrier with the worker's explicit validated-existing completion. Preserve fresh startup's existing Seed behavior and replay semantics. Do not start sync/API/dev tokens before acceptance.
3. **`fe-identity/src/file_fallback.rs`, `secret_store/run_local.rs`, and directory guide:** supply narrowly scoped load-existing primitives rather than copying seed decoding into main. They must not call generation, create-parent, migration/healing or set on retained startup. Inspect the actual stored secret values and ensure saved node-key secret and file represent the same true key if both are required. Missing secrets, including signer needed for serving, refuse; do not repair them while proving retention.
4. **`fe-database/src/lib.rs` plus a small existing-startup module and directory guide:** add a typed startup option with compatibility wrappers preserving normal behavior. The sole DB worker must establish existing store/namespace/database/schema and exact retained bootstrap owner, with a required real keypair and no local-node fallback, before applying any schema, publishing a handle, or running ordinary initialization. Require-existing skips schema creation, reconcile, asset migrations/backfill, role startup initialization and Seed. Recover HLC through read-only queries only after validation; publish readiness only after the entire accepted branch is complete. Reject later `DbCommand::Seed` in this mode as defense in depth. Static typed DbInitError refusals should identify failure classes without key/token contents.
5. **SDK boundary must be proven before live approval:** a nonempty directory check plus ordinary `Surreal::new::<SurrealKv>` is not a no-create guarantee. Review locked SDK store-opening/namespace-selection behavior and use a supported strict-existing mechanism or appropriate retained existing-entry protection. No new offline opener, helper connection, unsupported reader, fake namespace owner or metadata recreation is acceptable. If the locked SDK cannot establish that contract, keep the retained launch blocked. Logical no-init/no-seed is separate from an unsupported claim that the storage engine never performs housekeeping bytes.
6. **Guides and existing startup/lifecycle journeys:** document the strict mode and honestly distinguish launcher fixture suppression from DB admission. Author checks covering missing/empty store/namespace/schema, missing/corrupt/replaced key or secrets, wrong/missing/duplicate bootstrap owner, missing expected scope, readiness before full completion, Seed refusal, and unchanged fresh mode. Root owns one integrated execution sweep after all authorized fixes; this trace ran none. After source review, first use fresh disposable owned roots to validate refusal and success. Retained campaign root stays held until the reviewed contract and those checks justify release.
