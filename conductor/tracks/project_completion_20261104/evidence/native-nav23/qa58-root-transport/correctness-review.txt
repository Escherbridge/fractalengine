The public APIs are present in locked egui0.33.3; `accesskit_root_id` returns Id::new("accesskit_root"), and public Id::value matches the numeric conversion used by egui's crate-private accesskit_id. An arbitrary Window-shaped or previously normalized different-root tree cannot be substituted.

The host destination is only `ak::NodeId(root.window.to_bits())`, supplied by the already-owned current Window/context/handler binding (`raw/fractalengine/src/native_window_witness/provider_output.rs:55–61`). That matches Bevy_winit0.18.1's actual direct initial-tree root, which AccessKit_windows0.29.2 retains as a fixed-ID PlatformNode. An unchanged ID keeps that real initial root in successive full trees; it does not change which adapter/context owns it.

## Actual parent stop and pre-decode exit classification

`raw/tools/qa/native_observer/windows.py:219,235–244` adds a local flag, set only in the existing still-live kill branch when collector failure is not already set. The loop's other exit condition is its unchanged absolute deadline minus0.2s. After unchanged wait/join, classification is:

1. existing collector failure or live collector → worker_output_refused;
2. actual parent deadline-stop request → worker_deadline_stop_requested;
3. otherwise → worker_exited.

This reports the request, not proven cause of death. A process can naturally finish between poll and kill; the request flag remains meaningful even when the confirmed exit is0. CPython's Windows kill uses TerminateProcess(handle,1); exit1 remains compatible with parent termination, not proof of a C++ crash. No extra stop, enlarged deadline, output bytes or size guess was added.

If kill/wait/join throws, the existing BaseException cleanup still owns the result. A second failed kill/wait retains UNKNOWN_LIFETIMES/lease and raises worker_lifetime_unknown; unconfirmed start keeps its existing start ownership. A confirmed failure-after-start remains worker_failed_after_start. Live collector threads retain UNKNOWN_IO in finally. The new flag cannot turn those paths into successful/drained deadline results. A collector failure arriving during drain still wins over deadline classification.

`raw/controller.py:203–205` now requires exact integer exit0/2 before decode. This also rejects bool/float/string aliases. Controller execute/entry bytes are independently **identical to before**: it first durably appends the terminal receipt with actual exit/code, then reads independent ledger state, rejects non-worker_exited classifications, calls worker_output, checks live ownership and applies the existing ledger override. Thus a requested deadline stop or abnormal exit is not masked by a later empty/invalid JSON error. Unexpected exit remains in the durable receipt; no new receipt schema is introduced. The existing lifecycle reader's fixed-code and integer-range rules accept the new categorical code without weakening cleanup binding.

Reservation, intent, spent ledger, unknown attempt outcome, historical-stage pruning and pair/restart ownership code are untouched. No refused classification clears or retries an invocation. Entry's existing attempt_spent=null on unavailable/unknown results is not reinterpreted as a pristine ledger.
