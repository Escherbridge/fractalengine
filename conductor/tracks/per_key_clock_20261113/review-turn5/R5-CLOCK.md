F3 HANDED-OFF (fe-database/src/role_grants.rs owner, later round; security, fail-closed) - fe-database/src/role_grants.rs:622, with fe-policy/src/role_grants.rs:144 and :180 - the revoke frontier is off by one. A window is `[since, until)` and the frontier is W, the newest stored write of the revoked author, so the window ends at W and leaves W out. On re-judge, every peer demotes M's last write that the revoker saw. That contradicts spec 3.7 ("any version stamped above the frontier" is refused) and the user decision that a revoke cuts at what the revoker has seen. Spec residual risk 1 contradicts itself ("at or below" next to `[since, frontier)`). Fix: `Some(author_frontier(..).await?.map_or(0, |frontier| frontier.saturating_add(1)))`, and keep the empty frontier at 0. In the same change, the CLOCK5-02 leg (role_propagation_local_test.rs:386-429) must expect `until: write_hlc + 1` and assert `held_at(write_hlc)` is true. Until then, the leg pins the current behaviour.
F4 HANDED-OFF (owner of scene_publication/inbound.rs, later round) - fe-database/src/handlers/scene_publication/inbound.rs:607-610 - `pending_local_keys` protects an unpublished local key only while the journal `after_state` equals the stored row exactly. After a first remote merge changes another key, a second merge before publication finds them unequal and puts the cached winner back over the local value. The publisher then sees committed == winner, stamps nothing, and the edit is lost without any error. Fix: use the publisher's `journal_covers` rule (publisher.rs:260) in that check. Trigger: an offline edit followed by two or more remote snapshots before `recover()`.

F15 KEPT (verified) - publisher.rs:285-288 - a journaled tombstone (`plugin_tombstone` facts, node_history.rs:504) takes the relaxed path only while the committed tombstone is its own. ## Security review (replication path)

- Authn/authz: `prepare` still requires Editor through `prepare_scope_permission` (publisher.rs:61-67) and `require_committed_boundary(..., actor)` (node_history.rs:681). `journal_covers` never lets the actor sign a value it did not write. A key that differs from the journal is accepted only when a stored non-floor winner already holds the committed value, and stamp_own_versions never stamps that key as the actor's own (publisher.rs:340-353). A stale cache entry has no backing version (`load_stored_clock`), so it fails closed.
- Tombstone: the strict rule is unchanged (publisher.rs:96-130 plus `journaled = false`). A remote tombstone is never re-signed (F15).
- Clock: node_scene_clock is never lowered. `scene_clock = max(known, journal clock)` is bound to both CLOCK_WRITE and CLOCK_VERIFY (publisher.rs:146, :182-183), and CLOCK_FENCE guards the value read before. FIELD_CLOCK_FENCE and OWN_VERSIONS_FENCE (publisher.rs:207-209, fenced on `$scene_own_author`) guard the stamp inputs.
- Replay/forgery: a stale journal fact can only re-emit the actor's own stored versions at their stored hlcs (F8). The receiver checks the marker hlc against the actor's write-time Editor window (inbound.rs:310).
- Replication: no current-role check was added (merge_once uses `RoleLevel::None`, inbound.rs:533; see F14).
- No secrets are logged, and no new send path was added.
- SEC-INBOX 4: STILL-FIXED - fe-database/src/role_grants.rs:171-189 (`proven_windows`) and :518 (`place_statement` keeps only proven windows). A wire window can narrow but never widen. F3 is a separate off-by-one in local frontier derivation.
