FractalEngine @@PLATFORM@@ -- Quick Start
==========================================

FractalEngine is an alpha spatial analytics engine with a 3D scene editor
and peer-to-peer sync. This archive holds the desktop app, the sample
models it can load, and the licence files.

Build: @@BUILD@@


1. Run it
---------

@@RUN@@

Keep the "assets" folder next to the program. Besides holding the sample
models, its presence tells FractalEngine that it is running from an unpacked
download, so it keeps its database in the "data" folder next to the program
no matter where you launch it from.

3. Where your data and settings live
------------------------------------

  data/fractalengine.db   Your verses, fractals, petals and nodes (SurrealDB).
                          Created next to the program on first run.
  data/blobs/             Imported models (content-addressed blob store).
  data/p2p/               The peer-to-peer replica store.
  data/screenshots/       Window captures saved with the F12 key.
  data/panic.log          Crash details, if the app ever crashes.

  Settings (render distance, camera, relay, scale bar):
      @@SETTINGS@@
  Installed map tilesets (.hexon files): a "fractalengine/hexons/tilesets"
      folder under your per-user data folder (%LOCALAPPDATA% on Windows,
      ~/.local/share on Linux). Set FE_HEXON_DIR to use another folder.
  Node identity key: your operating system's keychain (@@KEYCHAIN@@). If the
      keychain is unavailable, the key is kept in a file under your
      per-user data folder instead.

To move or back up an installation, copy the whole folder, including "data".
Settings and installed map tilesets live outside it; copy them too. The node
identity key lives in the keychain (or its fallback file), not in "data".
To start from scratch, close the app and delete the "data" folder.

Upgrading from a single-file download (builds before 2026-10-13 shipped a
bare program with no "assets" folder): that build kept its "data" folder in
whatever directory it was launched from. To keep your verses, close both
versions and copy that old "data" folder into this folder, replacing the
new one if this version already created it.


4. Network and peer-to-peer sync
--------------------------------

  * The app serves a local HTTP/WebSocket API (with MCP tools) on
    127.0.0.1:8765. It listens on this computer only.
  * Peer-to-peer sync uses iroh 1.x. By default it goes through n0's
    public iroh relays, which are shared and rate-limited. For anything
    beyond a trial, run your own iroh-relay 1.x server and point the app at
    it, either in Settings > Network or with an environment variable:

        FE_SYNC_RELAY=https://relay.example.com     (your own relay)
        FE_SYNC_RELAY=disabled                      (LAN only, no relay)

    If you set both, the environment variable wins.
  * iroh 0.35 and iroh 1.x peers cannot talk to each other. Everyone you
    sync with needs a build from 2026-10-11 or later.

Other useful environment variables:

  RUST_LOG=debug    More detailed logs on the console. With RUST_LOG unset,
                    only errors are logged.
  FE_API_SCREENSHOT_ALLOW=0
                    Turn off the local API's screenshot and camera endpoints.
                    They are on by default, but only a token with Owner
                    rights for the open verse can use them, and only from
                    this computer.
  FE_API_INPUT_ALLOW=1
                    Turn ON input injection through the local API (off by
                    default).


5. Known limits (alpha)
-----------------------

  * The app is alpha software, and the files are unsigned. Windows
    SmartScreen may warn on first launch. There is no macOS build.
  * Op-log entries carry signature fields, but the legacy write paths store
    placeholder signatures. Do not rely on op-log integrity yet.
  * Anyone who holds a verse's sharing capability can write to it. Only open
    verses from peers you trust. See SECURITY.md in the source repository.
  * Models with KTX2/Basis textures are refused (from peers AND local
    imports) until the engine picks up an upstream decompression fix
    (RUSTSEC-2026-0344). Convert such textures to PNG/JPEG before importing.
    The refusal is reported in the console window only.
  * Unpack into a folder you can write to: the app keeps its database in the
    data/ folder next to the program.
  * Several recent editor features have not been fully checked in the
    running app.
